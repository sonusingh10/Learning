# Learning Repository Rules

This repository is a curated library of learning material, reference links, practical tools, and open-source projects. Keep it easy for a new reader to browse.

## Adding a GitHub repository

1. Link to its canonical GitHub repository page.
2. Check its public star count and include the check date. If unavailable, say so rather than guessing.
3. Check GitHub license metadata and license files. Record the declared license. Explain mixed or custom terms; write “unspecified” when none is declared.
4. Add or update the project-wide [GitHub Repositories Ranked by Stars](GitHub%20Repositories%20Ranked%20by%20Stars.md) list, sorted by the most recently recorded star counts. Keep the check-date note accurate.
5. Add a concise “why it exists” description based on the repository description or README. Do not invent a purpose.
6. Add the repository to its relevant topic note and keep its stars, license, and purpose consistent with the master ranking.

## Adding other resources

1. Add the resource to the folder that best fits its subject. Create a new category only when the current folders do not fit.
2. Link directly to the source and explain what a reader can learn or do there.
3. Update the category README and the root README directory so the resource is discoverable.
4. Preserve attribution and distinguish verified facts from claims copied from a supplied post. Add a checked date for details that change, such as pricing, features, availability, or star counts.
5. Check for a duplicate before adding an entry. Prefer updating an existing note when the same resource is already saved.
